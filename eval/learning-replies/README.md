# 学习回复评审：二十个固定问题

本轮只准备题目与评审规则，不运行真实模型。脚本 Provider 的测试只能证明提示接入、
预算、来源和隔离行为，不能证明自然讲解质量改善。
候选样稿见 [八组讲解样稿](../../docs/examples/learning-replies.md)。

| ID | 问题与来路 | 应重点判断 |
| --- | --- | --- |
| 01 | SQL 是什么？ | 能否用一张表和一条查询说明用途，必要术语是否解释。 |
| 02 | SELECT 和表有什么关系？ | 能否沿用 01 的数据，不重新从数据库历史开始。 |
| 03 | 函数参数是什么？ | 能否把参数位置、这次传入的值、返回值对应起来。 |
| 04 | greet("小林") 为什么得到这个结果？ | 是否跟随一次调用，而不是罗列参数分类。 |
| 05 | b = a 后为什么改 b，a 也变了？ | 是否区分名字与对象，是否有具体状态。 |
| 06 | b = a.copy() 后再 append 会怎样？ | 是否解释变化及嵌套可变对象的边界。 |
| 07 | 按钮变绿，刷新后数据没了，为什么？ | 是否给可核对的来路，而不是断言数据库原因。 |
| 08 | 这次 HTTP 请求从浏览器怎么走到后端？ | 能否追踪具体请求，静态线索与实测结果是否区分。 |
| 09 | Git 项目保存文件后，为什么索引仍是旧内容？ | 是否区分工作区、提交和索引版本。 |
| 10 | 接 09：听不懂，提交是什么？ | 是否先补该词，并沿用同一版本例子。 |
| 11 | 依赖注入解决什么问题？ | 是否用职责分离说明用途，避免直接灌模式术语。 |
| 12 | 把 db 作为参数传进来就算用了某框架吗？ | 是否区分机制、框架采用与证据。 |
| 13 | JWT 能读到内容，怎么还能验证？ | 是否分清签名和加密，说明校验边界。 |
| 14 | 这个项目哪里验证 JWT？ | 是否只凭真实项目证据给位置，不引用教学例子。 |
| 15 | 接 05：听不懂。 | 是否改变表示方式，仍使用 a、b 和原列表。 |
| 16 | 接 15：还是不懂，b = a 到底做了什么？ | 是否缩小到该步骤，而非再次输出完整教材。 |
| 17 | 接 05：换个例子。 | 是否尊重明确请求，在相同概念上换例并对应对象。 |
| 18 | 给定真实函数：入口在哪个文件哪一行？ | 是否直接定位，不强行安排教学长文。 |
| 19 | 一个新会话只问“听不懂”。 | 是否只问一个具体澄清问题，不借用另一会话。 |
| 20 | 当前索引没有命中某技术，能否介绍原理？ | 是否保留通用解释，同时不虚构项目位置。 |

## 运行前冻结

二十题分别比较当前基线与候选，共四十次回答。执行前记录两版提交、完整生产提示及 SHA256、
Provider/模型 ID、参数、默认输出上限、项目提交或无 Git 指纹、教材版本、每题会话来路和证据。
使用临时项目及独立会话，固定工具结果或同一索引，保留原始回复、结构化来源、延迟和失败记录。
连续题是同一组固定上下文，不把某一版临场生成的历史混入另一版；同时另测自然续聊路径。
本轮不提供假模型评分，不把预写样稿冒充实际 A/B 输出。

## 人工评审

每题按四项各记 0–2 分：问题是否得到直接解释；关键因果/状态是否能跟随；
必要前提与术语是否清楚；来源、不确定性与例子是否区分。
对续讲题另记“表示方式是否改变／是否沿用来路／是否尊重明确换例要求”。
记录具体问题，例如“把列表名当成对象”“只把引用改称指针”“仍未说明提交是什么”，
不以禁用词数量、标题数量或点击量替代理解效果。
项目事实或引用造假、未解决当前问题却要求做题，单独列为不可接受结果。
需要实际用户阅读，确认能否解释模块解决的问题、跟随输入或预测一处变化；不推断已经掌握。
