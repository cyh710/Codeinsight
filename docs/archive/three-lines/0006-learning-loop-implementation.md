## 接入内容

1. `LearningBridge.prepare_goal` 在目标消息剩余预算内整节注入教材，元数据独立保存。
   runtime 根据真实教材来源回答通用知识；项目问题、虚构位置仍要求代码证据。
2. 问答普通响应与 SSE 最终 answer 共用教材来源、有效学习目标、最多三个推荐入口；
   最终 `text` 用于替换流中尚未校验的正文。原有字段和事件名称兼容。
3. 增加三个全局知识端点、知识主题的项目实例端点和冻结代码阅读端点。
4. 代码阅读目标走原 `read_file` 工具的账本、引用和事件流程；校验项目绑定及源码哈希。
5. 前端维持三栏。右栏目录、搜索、章节与来源、项目实例、返回/前进和阅读位置；
   最终有效链接才可点击，失效目标保持文字，续问携带当前目标。
6. 项目切换保存各自对话、取消旧流、清除旧代码上下文；服务端历史同样按项目隔离。
7. API 概念解释复用 B 服务：低置信候选保持推断，deep 失败显示教材及已有证据。
8. 检测规则指纹映射至独立单调整数表，schema 1→2 原地迁移；教材/文案更新不重检。
   查询旧索引时可从对应 Git 快照补检，源哈希不匹配时保留可解释失败。

## 依赖与打包理由

- PyYAML：完整 YAML 本体不能靠标准库解析，已声明并写入 lock。
- remark-gfm：Markdown 表格属于用户已确认内容形式；react-markdown 本身不解析 GFM 表格。
- @playwright/test：只作开发依赖，用实际浏览器验证流式链接、导航、位置和项目隔离；
  测试后端使用临时 Git/SQLite 与假 Provider，不触发真实模型或生产数据。
- monaco-editor 显式声明原有 peer 依赖并本地打包 worker，仍延迟加载；
  代码阅读不再依赖 CDN，浏览器用例验证没有外部资源请求。
- wheel 纳入 66 篇文章、20 本体、来源清单与独立许可文件。资产从包或源码目录定位，
  不从被分析仓库或运行目录查找教材。
