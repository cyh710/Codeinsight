# ADR 0042 · 当前工作区优先，索引辅助，历史按内容恢复

状态：接受（请求0025，用户已对齐完整调整）。

## 原因

索引是寻找实现和分析结构的辅助，不应决定AI能否阅读用户的项目。旧索引快照解决历史可读性，却无法发现未索引的当前代码和实验记录。

## 决策

- 默认目录浏览、文字搜索和文件阅读直接访问项目工作区，仅读取授权根内文本；未指定版本的阅读器也采用此规则。
- 读取结果即时保存原始字节，并登记项目/路径归属；正文来源使用内容哈希，后续磁盘修改不影响历史跳转。每次问答对同一路径使用首次读到的版本，跨文件不声称原子工作区快照。
- 语义检索、符号与调用关系继续来自索引，结果明确标明索引版本，解释当前实现前读取当前文件核对。静态边不自动升级为当前工作区的关系。
- 历史索引链接继续按epoch/commit恢复；工作区链接按hash恢复。未注明版本的旧记录不补造身份。
- 搜索使用标准库、有界扫描、字面匹配，不执行shell、不依赖在线embedding。跳过缓存/二进制/密钥，跳过越界符号链接；结果告知跳过及截断，不能把受限扫描称为完整搜索。
- 复用file_snapshot记录workspace:<hash>，无需迁移。不自动更新索引或清理历史快照。

## 边界与重评

当前工作区在工具之间可能变化；同路径首次读取固定，但不同文件不是同一时刻的原子快照。需严格全仓版本一致的历史分析使用提交/索引快照。大型仓库的扫描性能若成为瓶颈，再评估原生搜索和增量缓存；不因本轮引入自动后台索引。
