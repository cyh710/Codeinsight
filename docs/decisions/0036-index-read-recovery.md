# ADR 0036：当前 schema 的校验只读，索引检查可恢复

- 日期：2026-10-27；状态：已接受；请求 0019。

WAL 允许读者在索引写事务持续期间读取上一次提交的状态，但正常 GET 在校验 schema 时
重复执行脚本，其中的项目身份高水位 UPSERT 把这些读者变成竞争写者。
延长 busy_timeout 只能延后错误，不能解决读取也申请写锁的问题。

当前版本只核对 user_version 后返回；建库与旧版本迁移仍执行完整脚本，数据库连接明确关闭。
新增表、索引或触发器必须升级 schema，不能依赖每次 GET 的隐式修补。损坏或缺失对象需要
独立诊断，不能在普通读取中无声改库。原地迁移及项目 ID 不复用约定不变。

前端检查在原有 150 次轮询上限内，对网络与 5xx 失败退避重试；失败也占用次数。
最后一次仍不可读则保留可手动恢复的错误，已拿到 indexing 但次数用尽则明确暂停。
onTick 用服务端最新详情更新状态，恢复时清除旧错误。取消只停止读取，不中止后台索引。
成功、错误和延迟回调都必须仍属于原项目检查，不能恢复已关闭或移除的提示。

若索引事务使正常会话写入仍受阻，需单独评估索引提交边界或存储拆分；本轮不改变
索引的原子提交语义，也不承诺写操作在持锁期间完全无等待。
