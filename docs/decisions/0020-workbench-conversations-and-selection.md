# ADR 0020：会话持久化与可恢复的阅读工作区

- 状态：用户已确认完整改版、多页签、单区阅读、切换继续生成、各会话独立材料、左栏切换。
- 日期：2026-10-25；请求 0007；替代 session.py 中“重启丢会话可接受”的首版假设。

## 决策

服务端 SQLite 保存会话及完整回合投影，关联原有任务账本；完整投影包含来源和请求阅读目标。
模型仍只使用最近六个有效问答对及焦点。失败、中断半轮不当作完成的模型历史。
每次请求有稳定 request_id，同一会话不能并行生成；不同会话的请求独立存活。
切项目/会话不取消流，关闭页面断开流则中断；服务启动标记遗留运行回合为中断。
增量和最终结果落盘后发出，取消显式处理，不得被 finally 误标为完成。

浏览器 IndexedDB 保存草稿、材料页签、阅读位置、来路和提问关联；布局另存 localStorage。
阅读关联有 follow/fixed/none 三态，取消后不能因滚动重新关联；材料固定与关联固定是不同状态。
页签身份包含版本；自动证据不会重新打开隐藏面板，也不会覆盖固定阅读。
代码选区为版本和 UTF-16 行列，教材选区为版本、章节和 UTF-16 原文范围；客户端正文仅预览。
前端利用现有 Markdown AST 源位置；服务端重读、验证边界和预算，不使用客户端片段作为依据。

## 代价与重评

默认单用户、单后端进程，本轮不做跨设备同步或脱离网页连接的后台任务。
历史账本缺少的元数据明确标缺失，不补造来源。布局偏好损坏可复位，记录存储失败明确提示。
若需要多进程任务执行、协同编辑或云同步，重新设计任务租约和工作区同步；不把当前实现包装成这些能力。
