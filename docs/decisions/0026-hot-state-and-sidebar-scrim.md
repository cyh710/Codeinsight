# ADR 0026：热更新保留状态与侧栏遮罩边界

- 日期：2026-10-26
- 状态：用户要求定位列表清空，复现后明确授权两处一起修复。

## 已验证原因

隔离源码副本中热更新 projectStore 后，项目数组从 4 变为 0；热更新 chatStore 后，
对话从 3 变为 0，DOM 行也变为 0。项目列表请求始终只有首次那一次，后续开关材料不恢复。
直接开关材料在宽窗口没有清空数据。根因是模块重新创建 vanilla store，而启动恢复只执行
一次，新的空 store 没有重新初始化。复现不修改当前工作区源码、不写实际项目或对话。

另一个独立缺陷出现在 1100／1024／900px：材料关闭按钮的实际命中元素是左栏遮罩，
一次点击会关闭左栏而保留材料。此时项目和对话数据仍在，但左栏变成 display:none。

## 修复与约束

使用 import.meta.hot.data 保留项目、对话、工作区、布局、视图和保存状态的完整容器身份。
保留闭包中的流控制器、客户端缓存、索引监视器与工作区激活代次；订阅只在首次创建时注册。
已有工作台热更新时不再次初始化或通过 URL 重开材料。生产构建没有 HMR，仍按原方式创建。

保留完整闭包意味着状态模块自身的逻辑修改需要手动刷新后加载；组件和样式照常热更新。
相较于自动整页刷新，这能避免打断正在生成的回答和重建草稿。手动刷新仍遵守既有中断规则。

左栏遮罩仅覆盖中间主区域，不覆盖并排材料区；单区材料阅读时不叠加左栏遮罩。
关闭材料只修改材料开关，项目抽屉仍可通过顶部入口关闭；不擅自重置布局或左栏数据。

隔离热更新回归须使用独立 Vite 缓存和复制的源码，禁止修改实际工作区来触发用户浏览器更新。
