# ADR 0044 · 修复并发、解析与版本边界

状态：接受；用户批准请求0027对应的七项审查修复。

## 决策

- 创建会话绑定发起时的项目和导航代次；迟到创建结果可留存服务端，但不接管当前界面。
- 索引构建使用隔离SQLite副本；源文件、解析、分词和关系检测不持有主库写锁。发布时只更新项目索引，重新映射并发分配的ID，保留最新会话、工作区来源和其他项目。发布前核对原索引身份，冲突时保留原结果并明确失败。
- 参数及局部赋值绑定使同名调用保持未知目标；低置信调用不通过全项目短名回退伪装成确定目标。解析器版本变化要求下一次索引重建，不偷偷更改现有用户索引。
- 引用范围只能由同一份来源身份覆盖；多版本有歧义时不生成链接，解释原文保留。范围与版本均保存在结构化来源中。
- 只读文件阅读器按真实内容哈希匹配当前索引符号，补回概念/关系入口；不同版本不套用行号或概念实例。
- 首次补齐来源身份是同一次导航，使用地址替换而非新增历史。
- 服务重启后遗留executing状态转failed，明确已中断；保留现有分支和工作树供人工处理，不自动续跑、不自动清理。

## 边界

SQLite最终发布仍是原子写事务；不承诺零等待。若外部进程长期独占主库写锁，仍需返回具体可恢复错误，不隐藏保存失败。单文件跨版本比较的裸路径引用有歧义时，可通过带完整来源身份的探索动作定位。静态分析不执行用户代码，不声称完整Python动态绑定解析。

隔离构建复制本地SQLite库，会占用额外临时磁盘空间；不复制或替换用户源码，构建结束后清理临时库。主库只发布索引表及新增变更记录，工作区快照采用不可变归属的追加合并。引用沿用当前工作区材料优先的规则；同一来源类型内多版本歧义不任意选取。
