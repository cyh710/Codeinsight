# ADR 0016：教材来源独立于代码证据，阅读目标由服务端重读

- 状态：已按用户确认计划实施；2026-10-24。
- 对应需求：知识探索计划；规格 §2.6；请求 0001、0003、0005。

## 原因

原 M3 只认可代码位置，会把“SQL 是什么”这类已有教材支持的问题当成未命中。
若简单放开弃答，又会把通用教材误当成项目已采用某技术的证明。
客户端传来的旧文章说明或源码片段也不能成为事实来源。

## 决策

- 本地教材检索作为独立来源，不参加代码检索五臂评测；项目实例仍进入概念臂。
- 同一版本文章用于目录、正文和检索。阅读目标传 ID/章节/版本，代码目标传项目/路径/行号；
  服务端分别从受维护资产或索引对应源码读取。客户端正文不注入模型。
- 教材整节使用目标消息剩余字节预算；没能纳入的章节不出现在“已引用”元数据中。
- 纯知识有实际资料可以解释；显式项目问题、未经验证的位置和项目断言继续要求代码证据。
  静态规则只判定证据资格，不宣称已经验证模型解释的语义真实性。
- 来源、有效正文链接目标和末尾推荐分开。普通答案和最终 SSE 输出相同投影，
  前端使用最终正文替换未验证增量；未落定或不存在的学习目标不启用链接。
- 阅读历史不修改对话。项目切换隔离服务端会话与客户端异步回调，知识本身保持全局。
- 概念 API 复用 B 解释服务，低置信候选不得升级；deep 失败仍可阅读本体和教材。
- 检测指纹独立编号并原地迁移。文字、知识索引与检测规则分别失效，不因改教材重跑概念。
- 保留现有三栏与主题。补接原有主题初始化，避免缺少 CSS 变量造成消息不可读。

## 代价与重评条件

当前按请求重建小型教材检索快照，保证版本一致，规模扩大后需引入按内容版本的缓存。
使用关键词和显式项目表达作保守的证据资格判断，不能代替真实模型效果/人工阅读验收。
当文章数量、长对话并发或知识版本热更新需要超出当前规模时重新评估缓存和存储结构。
人工样本精确率、完整召回率与学习体验仍分别报告，不把浏览器自动化当作用户研究。
