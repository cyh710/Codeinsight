# ADR 0024：保留历史的源码重新定位与现代系统窗口

- 日期：2026-10-26
- 状态：用户要求修复失效目录，并参考织忆更新文件夹窗口。
- 契约请求：`docs/requests/0009-project-relocation-and-modern-folder-picker.md`。

## 决策

重新定位按原项目 ID 执行，先校验 Git 根目录与有效 HEAD，再预留运行记录。
新路径和重建索引在同一事务内提交，后台失败回滚，历史对话和材料保留；旧答案中的
版本引用保留原值，不伪装成新版本证据。使用既有 index_run 记录状态，不增加数据库表。
索引或回答尚在生成时拒绝重新定位；重启恢复遗留的重新定位记录为失败，可重试。

原 `run_index` 在清空旧索引后立即提交，失败会丢失旧索引。增加仅用于全量重建的
`commit=False`，由重新定位服务统一控制事务；其他既有调用保持原提交规则。

织忆的目录上传入口用浏览器 `webkitdirectory`，能打开现代系统窗口，但不提供绝对
目录路径。这里需要读取 Git 对象，因此使用 Windows `IFileOpenDialog` 的文件夹模式，
保留现代地址栏、搜索和快速访问；以标准库 ctypes 在独立 STA 子进程调用，不上传文件。
维持本机访问限制、单个窗口、300 秒超时和取消返回 null；不回退到旧树形窗口。

## 代价与重评

全量重新定位期间占用 SQLite 写事务，其他写入可能等待；读操作使用 WAL 中的旧完整
快照。大型仓库若超出交互等待范围，应改为独立库暂存后短事务替换。
目录选择依赖本机 Windows 桌面环境；无桌面会明确报错。跨平台仍沿用 tkinter。
