# ADR 0034：执行分支与学习分支的历史兼容

- 日期：2026-10-27；状态：已接受；请求 0017。

两条特性分支从 main 的旧版本分开演进：学习分支的 schema 4 包含探索列，5 包含项目身份
高水位；执行分支曾以 schema 4 保存执行表，但没有探索列。只取更大的版本号无法判别结构。

集成版使用 schema 6，保留已发布的迁移路径，在 5→6 时按实际列结构补齐探索列，
幂等补建 execution_task 和身份高水位。已有执行记录、探索脉络和源码索引原地保留，
不通过删除数据库或重新索引规避分支分歧。两支真实历史 schema 另在临时数据库上验证。

项目移除的忙碌保护纳入 planned、executing、review 执行任务，沿用既有 409 错误，
避免项目级联删除执行记录、后台任务却仍持有隔离检出的情况。

执行状态在 execution_task 中变化，历史回合只保存最初快照；执行卡打开后应重新读取，
并轮询未结束任务。结果按项目、会话、消息与任务身份更新底层会话容器，再投影活动会话，
不能仅改当前屏幕的 messages。关闭卡片或切换会话后忽略其旧轮询结果。
合入后最多等待学习卡一分钟；失败时显示已有 error，不提前声称索引已经更新。

若未来存在更多独立发布的数据库结构分歧，应改为独立的迁移标识或正式分支版本映射；
本次只兼容这两条已存在的历史路径，不猜测未知 schema。
