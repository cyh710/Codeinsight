# ADR 0033：讲解围绕困惑选择表示方式

- 日期：2026-10-27；状态：用户批准，请求 0016。

统一覆盖定义、原理、例子、误区和取舍会把不同问题写成同一篇文章。
采用共享讲解原则和有界样例提示：定位直接给位置，过程跟随具体输入，机制展示状态变化，
设计问题对照约束与取舍；必要术语随用随解释，长文仍可在用户要求时完整展开。
策略是内部提示，不是用户可见的固定栏目，也不做额外模型分类。

八组预写样稿提供可审查的表达参照，运行时最多选择一个相关短例。
关键词匹配只用于选择表达参照，无法确定问题时不注入样例，不改变检索路由或证据资格。
样例不含可借用的项目引用。动态提示在目标资料装配后占用剩余消息预算；预算不足时省略，
不为样例挤掉原问题或选区。系统规则沿用原有系统提示通道。
每次工具交互后先按原算法选择资料和历史，只有剩余回合预算足够才附加表达参照。

续讲继承同项目、同会话最近有效解释；连续反馈从已有回合重建，不新增学情表。
记录的是“用户说没懂”而不是推断“用户没掌握”。优先沿用例子，减少当次新增概念，
改用具体输入、前后状态或单个步骤；未说明具体障碍时不编造障碍。
历史解释与样例均是表达资料，不能自动成为当前版本的项目事实。
调用方传入的空会话容器仍保留其身份，不能因长度为零而替换成另一个默认容器。

quick/project 与预算、模型次数、引用校验不变。deep 共享讲解规则，仍只返回已有 JSON 形状。
若真实模型对比不能稳定改善解释，重评样例选择和表达规则；正则与脚本 Provider 通过
不能作为自然讲解或学习效果已经改善的证明。
