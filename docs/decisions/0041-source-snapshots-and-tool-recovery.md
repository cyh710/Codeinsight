# 0041 · 固定源码版本，记住确定失败的工具操作

- 状态：用户授权实施（2026-10-27），请求 0024。

## 决策

索引文件身份保持原始字节 SHA256，不忽略空格、缩进或注释。保存完整字节到数据目录内的内容寻址快照；快照与项目/路径/哈希的归属单独保存。先写快照再发布索引，失败不能发布无法读取的新版本。旧缓存不自动清理，避免历史引用断裂。

读取先验证项目归属与固定版本，再读取快照；无快照时可从 Git 或磁盘恢复，但只接受哈希完全匹配的字节。LF/CRLF 转换只是一种恢复原始字节的候选方法，最终仍须命中原哈希；不把文本相似当版本相同。缓存损坏可从匹配原文修复，无法恢复则明确失败。

回答开始固定 epoch/commit，运行中索引变化不静默改用新版。永久性的文件版本失败在该回合按路径记忆；临时网络错误不当作永久失败。连续没有新材料时进入一次不调用工具的回答阶段，只整理已取得内容和缺口；这不是固定总轮次上限。保留取消、上下文预算与结构化来源。

运行代码指纹不包含 `.env`、密钥或用户源码。服务返回启动时指纹与是否需重启；启动器拒绝静默复用旧代码。只提示用户退出旧启动窗口，不按 PID/端口杀已有服务。

复用现有 `file_snapshot`，以 `source:<hash>` / `epoch:<n>` 命名空间保存归属和版本映射，不迁移数据库。历史阅读验证项目、路径与 epoch/hash 的绑定。仅当缓存损坏或不存在时恢复对应原文，不能靠片段拼回整份文件；可验证的旧文件在读取时缓存失败仍可返回，日志明确记录未保存。当前文件变化的提示为按需检测，暂不增加后台全项目扫描。

## 代价与重评

完整快照占用磁盘，内容相同的文件共享字节；归属按项目和路径隔离。未保存过的旧源码可能无法恢复，此时需要更新索引。未来若增加清理机制，须先明确历史阅读保留策略，不在本轮自动删除缓存。
