# 0017. 关系图只投影可定位的边，布局用确定性分列

- **状态**：已接受
- **日期**：2026-10-24
- **影响范围**：`api/structure.py`（`/projects/{id}/graph`）、
  `frontend/src/components/graph/`
- **源文档**：§2.2-6「交互式代码关系图」、§2.2-7「图节点与源代码双向跳转」

## 背景

`edge` 表在织忆上有 43135 条边，其中只有 12832 条能落到仓库内的具体符号
（`dst_symbol_id` 非空）。其余是调用标准库、第三方库，或 `getattr` 这类
静态分析定不了目标的动态调用。

如果把整张边表直接画出来，会遇到三个问题：

1. **悬空节点**：解析不到目标的边没有可跳转的 `file:line`，画出来也点不进去。
2. **力导向布局不可复现**：同一份数据两次打开位置不同，用户没法在两次浏览间
   对照同一条关系；力导向的随机种子也让前端不好写测试。
3. **一跳就可能二三十个邻居**：`prepare_chat_stream` 一跳有 22 个节点。
   竖着排成一列时，`fitView` 会把整张图缩到 0.2 倍，字糊成一片。

## 决策

三条规则：

1. **只投影可定位的边**：`dst_symbol_id IS NULL` 的边不进图。
   能定位但 `confidence < 1` 的边进图并画成虚线。
   节点上限 `max_nodes`（默认 80），截断时响应里 `truncated: true`，界面必须显示。
2. **布局是确定性的分列**：跳数 = 横向的带；带内超过 6 个节点折到下一子列；
   列内按上一带邻居的重心排序。同一输入永远得到同一组坐标。
3. **节点带 `concept_ids`**：源文档 §2.2 的例子是「登录接口 → 身份验证 /
   数据库访问 / Token 处理」——那三个词是概念，不是符号。图上点概念标签
   直接打开概念卡（§2.6 的双向导航）。

## 理由

- **不画悬空节点**：图上的每个节点都能双击跳到源码，这是 §2.2-7「图与代码
  双向跳转」的前提。宁可少画，不留点不进去的点。
- **确定性**：分列布局是纯函数，`graphLayout.test.ts` 直接断言坐标；
  力导向只能做截图对比。同一份认知在两次打开时长得一样，才能拿来讨论。
- **跳数本身就是信息**：分层告诉用户「这些是直接调用者，那些是二跳」。
  力导向没有这个语义。
- **截断要明说**：图看起来完整、实际缺一半，比明确说「只画了 80 个」更糟。
  这和「引用校验不过就删掉那句话」是同一条产品原则。

## 备选方案

| 方案 | 为什么不选 |
|---|---|
| 力导向（d3-force / cytoscape） | 位置不可复现；同一条边两次打开位置不同，难以对照；布局逻辑无法单测 |
| 引入图数据库（Neo4j 等）做邻域查询 | 当前规模（1.3 万条可用边）SQLite BFS 实测 0.27 秒，多一个服务不值得 |
| 把未解析的调用画成灰色占位节点 | 占位节点没有 `file:line`，双击无反应；用户会以为那是仓库里的符号 |
| 每跳限 12 个邻居、优先高度数 | 会隐藏低度数但正被问到的符号；截断是按预算，不是按重要性 |

## 后果

- **得到的**：图上的每个点都能跳转；布局可测、可复现；截断状态可见。
- **失去的**：动态调用（`getattr` 等）在图上不可见——它们仍出现在右栏
  「被调」列表里，带 `可能` 标记。跨仓库依赖也不画。
- **将来要付的**：节点上限 80 是硬编码在接口默认值里的；超过后用户只能
  缩小跳数或换中心。布局对超宽图（三跳 + 高分支）会产生较多交叉线，
  这是分列布局的固有代价。

## 重评条件

- 单次邻域点击后 p95 超过 1 秒（当前 0.27 秒，`max_nodes=80`、深 2）；
- 出现「必须看完整 300+ 节点邻域」的真实使用场景（而不是演示）；
- 前端需要把布局结果持久化或在服务端生成坐标时——那时布局要挪到后端，
  纯函数的约束仍然保留。
