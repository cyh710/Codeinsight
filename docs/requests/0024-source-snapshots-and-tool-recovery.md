## 目的与范围

修复仅因 CRLF/LF 差异而读取失败，以及同一失配文件反复读取的循环。新建/更新索引时保存完整源码字节，AI、右栏和代码选区共用同一读取服务。历史索引缺少快照时，仅接受哈希完全匹配的原文件、Git 对象或可恢复的换行形式；真实修改仍需更新索引，不能把新版文件当旧版。

同一回答固定索引版本。版本错误按文件与版本记住，不通过换行号重新尝试；读取失败保留具体原因。连续无新材料时要求模型使用已有材料完成解释，保留已有正文，不恢复固定模型轮次上限。正常有进展的工具调用继续运行。

启动器与 API 增加可选运行代码指纹，发现后端代码更新时提示重启，不能只凭同一数据目录就复用旧问答代码。已有服务不擅自终止。

## 契约增量

`docs/api-contract.md` 记录 root/health 可选 `runtime_revision`、`restart_required`；不改已有字段。代码读取可携带旧版本的内容哈希，必须验证它属于此项目曾索引过的文件，不能任意读取缓存。必要时以现有文件历史清单及磁盘快照维护项目归属，不迁移 schema、不增加依赖。

具体补充：代码端点增加可选 `index_epoch/head_commit/content_sha256`，返回可选 `index_epoch/workspace_changed`；引用及阅读目标增加可选 `index_epoch`。复用现有 `file_snapshot` 表，`source:<hash>` 保存项目/路径归属，`epoch:<n>` 保存索引版本的文件映射；仅修改 schema 注释，不改变结构或版本号。全量替换在同一事务发布，失败回滚。材料身份、URL 与跳行携带 epoch，旧页签不改指新版。

不自动修改用户源码，不自动实时索引工作区。旧索引更新需要用户已有“更新索引”入口或 CLI；缺失的旧源码不靠片段拼造。
