# 契约变更请求

> 三线并行时，**任何人要改契约文件，都在这里提一个请求**，由 A 线（集成方）统一改并同步三条线。

## 为什么要这个目录

三个 agent 各写各的分支，最贵的成本不是写代码，是**接口漂移**：
A 线改了函数签名，B 线按旧签名写完了，合并时才发现。

口头说"你把那个改成 X"是不可靠的——消息会丢、会被误解、事后没人记得。
写下来才有痕迹。

## 怎么提

1. 在**你自己的分支**上新建 `docs/requests/NNNN-<简述>.md`（编号连续，A 线统一分配）。
2. 模板：

```markdown
# NNNN. <一句话说清要什么>

- **提出方**：B 线 / C 线
- **日期**：YYYY-MM-DD
- **紧急度**：阻塞 / 不阻塞

## 要什么

具体到函数签名 / 字段 / 端点。

## 为什么

不这么做会卡住什么？有没有已经试过的替代方案？

## 影响

- 哪些文件要改
- 哪些调用点受影响
- 是否需要改契约文件（models.py / schema.sql / api-contract.md / types.ts）
- 是否破坏向后兼容
```

3. **不要自己改契约文件**。等 A 线改完、合并回你的分支。
