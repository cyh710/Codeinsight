# 请求 0008：导入项目使用系统文件夹选择框

- 状态：用户明确要求“导入改成选择文件夹”，按现有跨线授权接通前后端。
- 新增 `POST /local/select-folder`：在本机弹出系统文件夹选择框，返回
  `{root_path: string | null}`；取消返回 null，不创建项目、不建立索引。
- 仅本机访问可用；同一时间只打开一个选择框。原 `POST /projects` 保持兼容。
- Windows 使用系统 PowerShell / Windows Forms；其他桌面使用标准库 tkinter。
  选择框在独立进程运行，关闭或超时释放资源；不可用时返回统一错误与重试说明。
- 浏览器不能可靠获得目录绝对路径，因此不使用目录上传或猜测路径。
- 导入弹窗改为选择/更换文件夹，展示已选路径，保留可选名称、ref 及确认导入。
- 不增加第三方依赖，不改数据库，不推送远程。

## 实施验证

- 后端本次相关测试 37 项、前端单元测试 114 项及新增浏览器流程测试通过；
  Ruff、ESLint 和构建通过。Windows 原生选择框实测打开并返回现存目录，未提交导入。
- 本机运行中的旧后端需要重启加载新路由；重启命令被自动审批拒绝（blocked by policy），
  因此保留原服务运行。前端对旧后端 404 提示重启后重试，不显示误导的“项目不存在”。
