# CodeInsight 工作台第二轮界面巡检

日期：2026-10-25。基线：`codex/workbench-ux@17b56d6`，实际页面 `http://127.0.0.1:5173/`。

## 结论

当前已经具备可调整布局、多会话、持久化工作区、材料页签和选区提问。
上一轮“固定三栏、切视图丢草稿、没有刷新恢复”等结论不再代表当前实现。

剩余问题集中在三方面：操作后的落点不完整、状态说明和实际目标不一致、辅助操作太密太小。
应先修复可能覆盖输入或让用户无法完成操作的问题，再统一信息层级；本次不建议再更换配色或重做整体布局。

## 方法与边界

- 实际打开当前开发服务，使用现有会话、教材和已索引源码，不发送问答、不调用真实模型或 Embedding。
- 检查 1440、1280、1024、900、700px 的布局；未出现整页横向溢出。
- 浏览器复现与代码检查分别标注；代码确认的缺陷不冒充已在实际索引任务中复现。
- 浏览器使用独立测试上下文，不修改用户当前标签页的草稿或布局。
  正常打开已有会话会触发应用自身的已读状态更新。
- 没有提交导入、重建索引、修改应用源码、合并分支或推送，也没有重跑完整测试套件。
- 本轮截图和结构化记录位于 `.ci/ux-review-20261025/`。
- 以下优先级用于安排下一轮工作，不代表生产事故等级；建议方案尚未实施。

## 优先修复的操作问题

### U01 · 恢复问题会直接覆盖未发送草稿

**证据：浏览器实际复现。** 输入“这一段草稿应该保留”，点击旧回答的“恢复问题到草稿”，
输入框直接变成“SQL 是什么？”，没有替换提示或撤销入口。新草稿还会按现有机制自动保存，
因此自动保存不能解决这次覆盖。

建议：空草稿直接恢复；已有输入时提供“替换／追加／取消”，或至少保留一次可撤销的替换。
恢复阅读关联也应与这次操作一起撤销。

代码：[chatStore.ts:319](D:/yy2/CodeInsight/frontend/src/store/chatStore.ts:319)。

### U02 · 在关系图中“问选中段落”，没有回到对话

**证据：浏览器实际复现。** 主视图切到关系图，在右侧教材选中文字，点击“问选中段落”。
关联成功、没有错误提示，但主视图仍是关系图，输入框不可见。
处理函数尝试聚焦仍处于隐藏区域的 textarea，没有切换主视图。
代码选区的提问处理也有相同的视图切换缺口，但本轮未另行执行该分支。

建议：明确切回对话，保留图中心、阅读位置和草稿，再聚焦输入框，并显示选段预览。

代码：[KnowledgeArticle.tsx:108](D:/yy2/CodeInsight/frontend/src/components/learning/KnowledgeArticle.tsx:108)、
[FilePanel.tsx:48](D:/yy2/CodeInsight/frontend/src/components/evidence/FilePanel.tsx:48)。

### U03 · 材料菜单被教材工具条遮住，且不会自然收起

**证据：浏览器实际复现。** 阅读教材时打开“材料操作”，
“关闭其他页签”等选项的一部分被正文上方固定的“问选中段落”工具条覆盖。
鼠标点击被工具条拦截，浏览器自动化同样无法完成普通点击。

另核实：菜单点击外部、按 Escape 都保持展开；为继续巡检而通过脚本触发菜单动作后，也仍然展开。
后者是脚本触发，不把它描述成成功完成了被遮挡的鼠标操作。

建议：统一浮层层级，让菜单高于正文固定工具条；选项执行、点击外部或 Escape 时关闭，并返回触发按钮焦点。

代码：[RightPanel.tsx:123](D:/yy2/CodeInsight/frontend/src/components/evidence/RightPanel.tsx:123)、
[KnowledgeArticle.tsx:105](D:/yy2/CodeInsight/frontend/src/components/learning/KnowledgeArticle.tsx:105)。

### U04 · 阅读滚动后，提问目标仍显示旧章节名

**证据：浏览器实际复现及代码确认。** SQL 文章从首节滚到 `tradeoffs`，
输入框仍显示“SQL 是什么 · 跟随阅读”。滚动处理更新 `section_id`，没有同步 `section_title`。

这证明界面标签不可靠，不据此断言服务端一定读错了章节。
建议：章节 ID、标题和当前目录项一起更新；固定选区时保持原目标，并清楚区别于跟随阅读。

代码：[RightPanel.tsx:61](D:/yy2/CodeInsight/frontend/src/components/evidence/RightPanel.tsx:61)。

### U05 · 来源卡片显示行号，点击却没有把该行号和回答版本传给阅读器

**证据：代码确认，本轮未以真实回答来源点击复现。** 来源卡片显示 `path:lineno`，
点击处理却只调用 `selectFile(path)` 或 `selectSymbol(qualname, path)`。
文件分支因此使用默认第 1 行；符号分支也无法按该命中行定位。
来源卡片还没有沿用回答所属版本，而普通引用入口已有版本传递逻辑，两个入口行为不一致。

建议：来源入口统一携带项目、文件、行范围和可获得的版本；缺版本明确标记，不能借当前索引假装旧回答的快照。

代码：[EvidenceList.tsx:20](D:/yy2/CodeInsight/frontend/src/components/evidence/EvidenceList.tsx:20)。

### U06 · 导入文案说在后台索引，弹窗却一直阻塞到轮询结束

**证据：代码确认，未实际启动索引。** 弹窗的提交函数等待 `importProject` 完成后才关闭，
而该函数在 `POST /projects` 返回后继续等待 `waitForIndexing`。
在此期间 `importing=true`，取消和关闭也被禁用。

建议：服务器接受任务后即可关闭弹窗，进度留在项目区；明确区分“关闭弹窗”和“取消索引任务”。
索引失败提供原因和重新操作入口，不要求用户停留在提交窗口。

代码：[ImportProjectDialog.tsx:43](D:/yy2/CodeInsight/frontend/src/components/tree/ImportProjectDialog.tsx:43)、
[projectStore.ts:157](D:/yy2/CodeInsight/frontend/src/store/projectStore.ts:157)。

## 当前环境另有一项未完成接通

前端已有“选择文件夹”，但实际 8020 服务的 OpenAPI 中仍没有 `/local/select-folder`。
这是运行中的后端尚未加载新代码，不是本轮又发现了一个目录选择实现缺陷。
上一轮重启命令被自动审批拒绝，原因是 `blocked by policy`；本轮没有再次尝试结束服务进程。
当前前端针对旧后端会提示重启，不能把这条用户路径报告成已经在当前服务里可用。

## 推荐顺序

1. 先修 U01–U05：保护草稿、正确回到对话、菜单可点击、目标标签准确、来源落到对应位置。
2. 接通当前导入服务，并处理 U06 的异步反馈；不把后台任务变成必须等待的弹窗。
3. 再统一 U07–U11：搜索范围、字号和点击热区、列表辨识、材料控制层级、教材章内导航。

后续验收应包含完整操作链，而不只检查按钮存在：
“写草稿 → 看关系图 → 选教材段落 → 回到输入框 → 恢复旧问题并取消替换 → 打开来源到原行 → 搜索并跳到命中章节”。

本报告是当前页面巡检和代码审阅，不是人工满意度调查，也不据此宣称真实模型的回答质量已验收。
