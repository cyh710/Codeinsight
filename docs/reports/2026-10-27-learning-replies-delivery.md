# 面向理解的回复策略：离线交付

日期：2026-10-27。基线 88c8c24，分支 codex/learning-replies。请求 0016，ADR 0033。

## 实现结果

- 主问答与概念深度解释共用讲解规则：定位直接给位置，过程跟随具体输入，机制展示状态，
  设计问题解释约束与取舍。撤去 deep 必须依次覆盖“直觉、机制、例子、误区和取舍”的要求。
- 正文使用自然中文，必要术语随用随解释；按问题选择表格、短代码或示意，不要求固定栏目。
  可靠通用原理可以直接陈述，未经确认的项目解释仍须标注推断。
- 新增七个可选短例与一个连续续讲的评审样稿组。主问答最多选择一个相关短例，
  八组完整样稿不整篇送入模型；无法确定相关性或预算不足就省略。
- 动态表达提示最多 1800 UTF-8 字节；原问题、选区、已有工具资料和历史先按原算法装配，
  仅在剩余预算足够时附加。工具内容增加后，样例可以自然省略，不额外扩大上下文。
- “听不懂／换例子／画图”等明确请求从当前项目、当前会话最近有效回合恢复来路。
  连续反馈记录原问题、明确请求、最近解释的片段，用于改换表示，不推断能力或“已经掌握”。
  续讲默认沿用原例子；明确要求换例时遵从。知识或代码仍走原有重新取证与版本检查。
- 最近反馈从已有 SQLite 回合重建，可跨后端重启恢复；CLI 从既有六轮窗口读取，
  不新增学情表、用户等级或公开接口字段。
- 历史与样例只作为表达数据，不成为项目证据；历史中的标签边界转义，引用资格仍由原流程验证。
- 修正空会话容器被真假判断替换的问题，保留调用方传入容器的身份及原始问题记录。

保持 quick/project 不调用模型。主问答默认 max_tokens=2000、temperature=0；
deep 保持 max_tokens=3500、temperature=0 和原 JSON 响应契约、24KB 材料预算。
无额外模型分类、改写或评分调用，不增加依赖，不改前端、SSE、领域模型或数据库 schema。

## 可审查的讲解资产

- [八组评审样稿](../examples/learning-replies.md)：SQL、函数参数、列表共享、浏览器请求、
  Git 版本、依赖注入、JWT，以及同一例子的连续两轮“听不懂”。
- [二十题评审方案](../../eval/learning-replies/README.md)：包含定位、续讲、跨会话、无证据、
  状态变化和设计边界，并明确未来同模型、同证据 A/B 的冻结与原始回复记录要求。

完整样稿用于人工对齐，运行时短例独立用于表达参照；它们都不是实际模型效果记录。
关键词只选择可选参照，不宣称完成问题语义分类，也不改变检索路由。

## 验证边界与启用

本轮真实模型调用为 0，脚本 Provider 只验证接入和边界；不证明自然语言讲解已经变好。
下一步真实效果验收拟固定二十题，对基线和候选各生成一次，共四十次回答，
记录引用真实性、因果/状态是否可跟随、前提与术语是否清楚，以及续讲是否改变表示方式。
本轮没有执行或捏造这份 A/B 结果，也不把样稿和模型效果混报。

重启后端以加载新提示和策略，无需重新索引。用户实际服务未被强制停止。
本轮本地提交，不合并主线，不推送；既有 `.zcode/plans/` 保持原样，不纳入提交。
