# 索引加载反馈与列表状态恢复交付

## 导入和索引反馈

导入提交时显示等待图标与请求状态，锁定重复提交和请求输入。202 后关闭弹窗，以工作台
顶部的紧凑状态条继续显示项目名称、等待时间和运行状态；隐藏侧栏或切换视图后仍可看见。
只显示接口已确认的状态，不显示百分比或伪造扫描、解析阶段。等待时间为当前页面观察时长。

首次文件树显示准备占位，避免“没有匹配的文件”和空白项目名。等待期间可写草稿或浏览教材。
完成后先同步文件，再展示真实文件与符号数量；可查看文件或关闭提示。

轮询、界面同步、失败及检查暂停按项目隔离。切项目不会被后台结果覆盖；刷新后恢复当前
运行项目的检查。网络中断和五分钟检查上限提供继续检查，只读恢复，不自动重复导入。
真实索引失败可按记录的原路径、名称和 Git ref 明确重试；没有原请求时可重新选择目录。

后端正常导入先预留 index_run，避免重复导入时旧 ready 让前端提前结束加载。复用原子
索引服务完成同一条运行记录，失败保留旧索引，重启中断可重试。保留显式 tag／commit，
避免固定版本索引被误与当前 HEAD 比较而显示过期。不增加依赖或新接口。

## 列表变空的定位与修复

已在隔离源码副本复现：热更新 projectStore 后项目从 4 变为 0；随后更新 chatStore，
对话数组和 DOM 行从 3 变为 0，且仅有首次项目列表请求。新容器被创建，启动恢复没有
重新执行，开关材料时的新一轮渲染会暴露空状态。数据库中的项目和对话仍然存在。

修复为通过 HMR data 保留完整状态容器与闭包，覆盖项目、对话、工作区、布局、视图、
IndexedDB 连接与保存状态。保留流控制器、客户端缓存和索引监视器，避免重复注册订阅。
已有工作台不因热更新再次初始化或重开材料。状态模块的逻辑更新需手动刷新后加载，
组件与样式照常热更新；此取舍记录在 ADR 0026。

另复现窄窗口材料关闭按钮被左栏遮罩覆盖，点击实际命中“关闭项目侧栏”。此时数据仍为
4 个项目、3 个对话，但左栏被隐藏。修复遮罩边界：不覆盖材料及拖动分隔条；单区材料
阅读不叠加该遮罩。关闭材料只影响材料开关。

## 生效方式

本次未结束已有服务，也未提交或推送远程。首次接入状态保留修复需要刷新页面一次；
后端运行记录修复需要重启启动器加载。重启前没有进行中的回答时，在启动窗口 Ctrl+C，
重新双击启动器并刷新工作台。用户索引、历史对话和已保存工作区保持不变。
