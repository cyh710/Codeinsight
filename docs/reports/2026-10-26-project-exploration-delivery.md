## 已实现的完整路径

新建会话显示真实项目导览 → 点击明确的追问 → 阅读问题驱动的解释与局部静态关系 →
打开编号来源 → 从本回合进入相关知识 → 继续追问且保留原草稿和关联 → 切换会话 →
刷新或重启后恢复来源回合、材料及探索脉络。

| 区域 | 交付行为 |
|---|---|
| 项目导览 | 索引文档摘录带出处；最多四项入口来自程序入口、成功变更、可靠概念证据和设计说明。无证据省略，不自动调用模型；已有对话可从工具栏展开 |
| 回答策略 | 取消统一 400 字和固定教材段落；定位、过程、设计与基础问题分别组织。原上下文预算、模型轮次和输出 token 上限保持不变 |
| 来源 | 普通正文的已校验引用显示 `[1]` 等编号；点击打开回答版本源码。完整路径/行号保留在来源区和复制文本中，代码块、行内代码、已有链接不自动改写 |
| 局部关系 | 可选结构化节点、职责说明及静态调用/包含/导入/继承关系；核对实际索引，低置信关联明确标记。无法核对的边移除，不冒充执行轨迹 |
| 后续探索 | 内部 `propose_exploration` 工具提交可选建议；服务端最终校验，最多三个追问/源码/知识/关系/时间线动作，不再叠加旧推荐 |
| 直接追问 | 从已保存回答或当前概览重读问题与阅读快照；已有草稿、关联和固定材料不被覆盖。同会话生成中禁用，不排队；沿用请求去重 |
| 项目知识阅读 | 从项目回答进入时显示本回合已展示要点、真实源码位置、相关教材章节，并提供全文及返回来源回答。没有解读时展示章节，不补造项目讲解 |
| 概念卡 | 优先当前代码范围或同文件的可靠实例，其次明确展示其他项目位置；无实例退回通用解释。quick/project 不调用模型，额外项目分析由明确追问发起 |
| 恢复 | 局部材料绑定项目/会话/来源请求/章节版本；全文仍按文章版本复用。URL、页签、导航和阅读位置沿用现有机制 |
| 探索脉络 | 折叠展示当前问题和最近十二条已展示要点，可定位回答或清空；最多 4KB 注入原预算。索引更新标旧、重新取证，不推断用户已掌握 |

## 阅读体验评审与边界

已检查真实页面截图：保留原浅灰天蓝风格，探索入口采用问题/收益列表，正文编号减轻路径
干扰，材料区并排展示项目位置及相关章节。界面检查不等同于初学者理解效果验收。

本轮真实模型调用总数 **0**。以下结果尚未声称通过：真实 Provider 是否在不同问题下适当选择
局部关系、正确解释设计取舍与文档冲突，以及初学者是否能解释模块作用、预测修改影响、找到验证源码。
这些需要真实模型及人类阅读评审，不能用脚本答案、点击量或停留时长替代。

建议人工沿上述三项任务分别记录“能独立解释 / 需提示 / 尚未理解”，同时记录错误解释和
找到的源码位置；不建立用户能力画像、不自动记录课程进度。
