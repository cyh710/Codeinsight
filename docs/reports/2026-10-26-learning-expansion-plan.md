## 3. 各种表达形式怎么用

| 内容需要 | 推荐形式 | 示例与约束 |
|---|---|---|
| 并列条件、操作前检查 | 短列表 | “启动前确认当前目录、解释器、端口”，不把连贯推理拆成碎片 |
| 有先后顺序的操作 | 编号步骤 | 建表→插入→查询，给出每步可观察结果 |
| 包含、分类、文件组织 | 目录树或层级列表 | 仓库目录、数据保存位置；表示包含关系，不画成调用关系 |
| 执行、传递、依赖方向 | 流程图 | print 与 return、请求经过后端；箭头旁说明传什么或何时发生 |
| 不同对象之间的交互 | 时序图 | 浏览器、API、数据库之间的一次请求，必要时分成功/失败情况 |
| 数据及约束关系 | 数据表与关系示意图 | 主键/外键、JOIN 前后结果，标注实际方言 |
| 随时间变化的行为 | 状态图或前后对照 | 草稿→保存中→已保存/失败，区分界面状态与持久化事实 |
| 多个方案的适用边界 | 比较表 | 内存、IndexedDB、SQLite 在刷新/重启后的差别 |
| 需要辨认实际工具界面 | 裁剪截图与标注 | DevTools Network、终端输出、真实代码位置；记录版本及采集条件 |

同一篇可以只用一种或不用图。每幅图必须回答一个文字不容易迅速看清的问题；没有信息增量的装饰图不列为交付。

## 4. 三篇样章的具体编排

### 样章 A：函数已经打印了结果，为什么拿到的是 None？

体裁：机制解释。基于现有 Python 函数文章修订。

1. 从现有最小函数运行结果切入，先记录 `36` 与 `None`。
2. 给出执行示意图，分别指出屏幕输出与调用者获得的值。
3. 替换 `print` 为 `return`，对照调用处如何继续计算。
4. 用 `12 / 36 / 36` 核对默认、位置和关键字参数。
5. 用实际调用位置解释返回值与副作用，练习根据误解选择，数量不预设。

图的作用：解释数据去向。代码、输出和正文都保留，图片不承载唯一解释。

### 样章 B：SQL 中的表，怎样关联成一个查询结果？

体裁：操作与数据观察。修订入门，并衔接约束/关联查询文章。

先用实际行列展示两张小表，再标注主键与外键，运行 JOIN 后显示结果表。让读者看见“行怎样匹配”，再解释一对多、没有匹配与重复结果。

各语句明确使用 SQLite 或 PostgreSQL；纠正原有折扣表达式和改名说明。截图仅在需要辨认工具或输出时使用，查询结果优先采用可复制表格。

图的作用：表达数据关系。不能把同名字段连线就解释成已存在外键约束。

### 样章 C：为什么列表刚才还在，切换或刷新后却没了？

体裁：故障调查与边界对照。以真实事故记录为依据，作为新增状态主题的样章。

先区分“数据真的为空”和“界面没显示”。用证据说明 HMR 重建 store 与遮罩关闭左栏是两种原因，再画数据所在层级，比较重渲染、卸载、HMR、网页刷新、后端重启。

配一张状态归属树、一张存储边界表；真实界面截图只用于显示必要的诊断现象。发布项目实例前绑定可读提交，不能用未提交修复伪造索引事实。

图的作用：帮助定位边界。这篇不复用 A 的逐行讲解结构，也不强行补三道题。

三篇样章是推荐选题；与上一份调查的样章方向相比，加入 SQL 数据关系以覆盖图文能力，保留机制解释与真实故障调查。最终选题在实施前随节奏一起确认。

## 5. 阅读器与资产实现建议

### 5.1 资源归教材管理

建议组织为：

```text
knowledge/learning/
├── index.json
├── articles/              正文、稳定章节与图注
├── assets/                SVG 图示、PNG/WebP 真实截图
│   ├── python-functions/
│   ├── sql-database/
│   └── state-lifecycle/
└── assets.json            资源 ID、所属章节、摘要、作者/来源/许可、内容哈希
```

图示保留可编辑源，正式阅读使用预生成 SVG；截图保留必要采集记录。简单树用语义化嵌套列表即可，复杂关系用矢量图。首版优先复用依赖，不引入运行时 Mermaid；以后确有大量时序图维护需要时再评估生成工具。

内置资源由后端的受控教材资源端点提供，并随 Python 包一起交付，离线可读。具体路径及响应字段先走 `docs/requests/`，不把本提案中的路径当作冻结契约。

资源修改参与教材版本与快照指纹；按内容哈希定位的 URL 避免缓存把新正文配上旧图。旧页签沿用已有版本失效提示，不能悄悄替换其阅读目标。

### 5.2 阅读操作

- 图随阅读宽度适配，文字保持可辨；窄区域改用纵向图或拆图，大图提供放大/原尺寸查看。
- 放大后可用按钮和 Esc 关闭，关闭回到原焦点与滚动位置。图不会自动抢走提问目标。
- 图片预留尺寸，异步加载不应推移原章节位置；返回材料与刷新恢复都要覆盖有图情形。
- 每张图有短图注、替代说明，复杂图在相邻正文解释关系。加载失败仍能读正文及图意，并可重试。
- 正文列表、表格和图注使用正常可选文字。表格在窄栏可横向浏览，保持列名可理解。
- 保持现有字体与紧凑布局，不为每个图、列表再套大卡片和重边框。

### 5.3 与 AI 和选区的关系

现有模型通过教材文字通道获得知识，不默认获得图片视觉能力。正文须包含图表达的关键事实，图片地址和矢量路径不充当知识。

精确“问选中段落”仍按 Markdown 原文范围校验，覆盖列表、表格与图注。跨图选择时明确范围包含的是文字/图片引用，不宣称选中了图中的某几个节点。

如增加“问这张图”，首版建议关联图所在的现有知识章节，并明确显示章节范围；不把 SVG 标签的 DOM 文字硬映射成 Markdown 原文选区。独立图目标与多模态问答另行评估，不暗中扩展成本与契约。

## 8. 验收标准

内容：已知错误修复；示例、输出与答案实际执行；版本、方言、来源、许可齐全；图意和正文一致。每篇的组织由问题决定，统一的是事实标准与资源维护方式。

阅读：材料宽 360/480/720px、展开阅读与 900/1024/1280/1440px 视口可读；图可以放大关闭，列表和表格可复制；加载失败不阻断全文；浏览器缩放和键盘操作可用。

探索：从回答进入章节→看图→选中文字提问→打开项目证据→返回原文，草稿、阅读目标、位置不丢；图片加载不制造滚动漂移；图片更新不出现版本错配。

验证：针对性 pytest、Vitest、Playwright，Ruff/ESLint 与构建；涉及公共契约和全局快照时按影响范围运行回归。离线脚本化 Provider，默认真实模型调用为 0。自动化通过与初学者阅读体验分别报告。
