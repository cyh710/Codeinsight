# 路线图 · CodeInsight

> 本文的阶段划分**逐条对应**《项目完整概览》的章节号。
> 源文档：`CodeInsight_项目完整概览_四人版.pdf`（12 页）。
> 里程碑的实际执行状态看 `docs/decisions/` 里的 ADR 与各阶段 commit。

---

## 一句话

让 Agent **持续维护**对一个真实仓库的认知——符号、调用关系、**技术概念**、版本演进、设计说明——
并把这份认知同时用于问答、变更解释与原理讲解。

系统以**理解为主线，开发为辅助，学习按需展开**：CodeInsight 负责"读懂并讲清楚"，
实际的代码修改交给外部 agent（Claude Code / Codex 等）经 **MCP Server** 调用本系统的理解能力。

## 三个贯穿全程、不可砍的部分

| | 源文档位置 | 为什么不能砍 |
|---|---|---|
| **知识探索** | §2.6 · §5-4 · §4.3 · §10 | 出现在源文档八处（标题、定位句、痛点、目标、四层、工作流、创新点、成果）。它是"理解技术原理"这半句话的落点 |
| **持续认知 + 设计说明过期检测** | §2.4 · §2.5 | 源文档标注为「重点特色功能」；§2.4 第 5 问「哪些历史设计说明已不再适用」是它最硬的一块 |
| **评测对照实验** | §5 · §6 | 源文档自己写明「以上属于拟实现的技术特色，**其实际有效性需要通过实验验证**」——这是它交给我们的任务 |

## 每阶段的验收

| 阶段 | 验收标准 |
|---|---|
| M1 | 真实仓库建索引成功；符号与调用边 SQL 查得出；超大符号正确二次切分 |
| M1.5 | 概念实例列表人工核对准确率 ≥ 0.8 |
| M2 | 10 个"在哪里实现"的问题全部给出正确 `file:line` |
| M3 | 上下文截断不破坏 `file:line`；事实与推断分栏；检索无命中时明确弃答 |
| M4 | 首屏 30 秒看懂项目结构；概念可从代码找到、可从概念回到代码 |
| M5 | `ci eval` 一条命令产出对照报告，含 95% CI 与样本量 n |
| M6 | 改一个函数后重跑索引，只有相关 chunk 的 `source_sha256` 变化（SQL 断言） |
| M7 | 外部 agent（Claude Code）能真的调通 `search_code` / `explain_concept` |
| M9 | 源文档 §9 收尾五条全部满足 |

### §9 收尾五条（最终验收清单）

> 「第一版重点保证**项目解析可靠、代码定位准确、结构关系清晰、变更认知可更新、
> 用户能够自然地进行深入探索**。」

## 里程碑与 ADR 的关系

每个阶段的**技术决策**都写进 `docs/decisions/`（ADR），**功能范围**写在本文。
两者分开：范围会随进度调整，决策会留下"为什么当时这么选、什么条件下该重评"。

见 [`decisions/README.md`](decisions/README.md)。
