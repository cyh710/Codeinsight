# 延迟初始化与缓存工厂

## 先建立直觉 {#overview}

延迟初始化把创建资源推迟到第一次需要时，缓存工厂可以复用已经创建的对象。无参数工厂配合缓存常表现为进程内共享实例，但不等于跨进程的全局唯一对象，也不一定保证并发首次调用只构造一次。

## 原理与执行过程 {#mechanism}

工厂函数封装构造过程，缓存按参数保存结果。无参数时只有一组调用键，后续调用可以返回同一对象。带参数时则可能创建多种实例。functools 的缓存需要关注对象寿命、清理和并发首次未命中；仅看 @lru_cache 无法直接认定严格单例。

## 跟着例子理解 {#example}

以下是独立教学示例，不代表被分析项目的实际代码。

```python
from functools import lru_cache
@lru_cache(maxsize=1)
def get_catalog():
    return {"version": 1}
print(get_catalog() is get_catalog())  # 顺序调用中为 True
```

## 一步一步读懂 {#walkthrough}

第一次调用建立字典，后续顺序调用复用缓存结果。修改这个字典会影响所有使用者，因此共享的配置或目录最好只读。清除缓存后还可能重新构造。项目使用多进程时，每个进程通常有自己的缓存，不会因为同名函数自动共享内存。

## 常见误解 {#pitfalls}

延迟初始化不自动解决线程安全。把可变用户状态放进全局缓存可能串用户。缓存对象可能长期保留文件或连接，需要明确关闭时机。参数变化和版本变化也可能使旧对象过期。

## 工程中的取舍 {#tradeoffs}

延迟创建减少启动成本，却会把首次延迟和失败推到用户操作时。显式应用生命周期更便于初始化与关闭资源。选择缓存工厂时，应确认共享范围和失效机制，而不是仅为了减少一行构造代码。
