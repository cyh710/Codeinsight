# 程序怎样执行：从源文件到结果

## 先建立直觉 {#overview}

程序是写给计算机的一组明确指令，源代码是这些指令的文字表示。Python 解释器负责读取程序、理解语法并执行操作；把代码保存成文件，并不等于代码已经运行。先分清“写了什么”和“实际执行了什么”，才能读懂项目入口。

## 原理与执行过程 {#mechanism}

可以把执行过程拆成读取源文件、解析语法、编译为代码对象和执行四个阶段。Python 通常先把代码编译成字节码，再由运行时执行；它不是简单地逐字符翻译。解释器遇到导入语句时会寻找模块，模块顶层语句通常会在首次导入时执行。函数定义建立一个可调用对象，只有调用才进入函数体；类定义中的类体则会在定义时执行。读项目时，应先找启动命令与入口，再追调用，不能按文件夹顺序猜执行顺序。

## 跟着例子理解 {#example}

```python
print("准备")

def greet(name):
    print("你好，" + name)

if __name__ == "__main__":
    greet("小林")
```

## 一步一步读懂 {#walkthrough}

第一步，解释器执行顶层 print，输出“准备”。第二步，def 建立 greet 并绑定名字，此时还没有问候语。第三步，直接运行文件时 __name__ 是 __main__，条件成立，才调用 greet。第四步，函数体执行，拼接字符串并输出。若把该文件作为模块导入，顶层“准备”仍可能输出，但入口条件不成立，因此不会自动问候。这也是为什么导入时触发网络请求常常令人意外。

## 常见误解 {#pitfalls}

语法错误可能让整个文件在执行前就失败；运行时错误则发生在已开始执行之后。看到函数定义不能认定生产链路调用了它。缓存的 .pyc 文件也不等于当前工作区的每行代码都已执行。项目使用哪个 Python 版本和环境，会影响依赖以及行为，应与启动命令一起确认。

## 工程中的取舍 {#tradeoffs}

把启动逻辑放进 main 函数可以减少导入副作用并方便测试。懒加载可以缩短启动时间，却把部分错误推迟到首次使用。需要复现一个问题时，先固定解释器、依赖、命令和输入，比反复修改代码更有效。阅读源码只能说明可能路径；是否实际经过该路径还需要日志或运行证据。
