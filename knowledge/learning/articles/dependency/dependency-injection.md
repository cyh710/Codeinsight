# 依赖注入：把需要的能力交进来

## 先建立直觉 {#overview}

依赖注入让函数或对象接收所需服务，而不是在内部固定创建所有依赖。例如，保存消息的服务接收数据库访问对象，测试时可以换成临时实现。它让依赖关系更显式，也便于控制生命周期。

## 原理与执行过程 {#mechanism}

最简单的注入就是参数。框架可以根据声明建立依赖图，解析请求参数、创建会话并在结束时清理。依赖注入不要求庞大容器，也不能自动保证接口语义一致。作用域决定依赖是每次调用、每个请求还是整个进程复用。

## 跟着例子理解 {#example}

以下是独立教学示例，不代表被分析项目的实际代码。

```python
def greet(user_id, load_user):
    user = load_user(user_id)
    return f"你好，{user['name']}"
result = greet(7, lambda user_id: {"name": "小林"})
print(result)
```

## 一步一步读懂 {#walkthrough}

greet 不知道用户来自数据库、文件还是测试数据，只依赖 load_user 的约定。调用者提供实现，函数保持业务职责。真实接口还要说明查不到时返回什么、可能抛什么异常以及资源由谁关闭。把依赖作为参数也让阅读者更容易追到替换点。

## 常见误解 {#pitfalls}

全局变量只是隐式依赖，不是天然的注入机制。测试替身若返回不可能的成功形状，会掩盖生产问题。框架的 Depends 名称需要确定来源；同名自定义函数不能直接认定为 FastAPI 依赖注入。

## 工程中的取舍 {#tradeoffs}

显式参数简单、透明，复杂依赖图可以交给框架。但过度抽象每个小函数会增加装配成本。先在外部边界注入难替换或有副作用的依赖，通常能以较小成本获得测试与维护收益。
